# 上传识别与画面可读性

上传的图片、视频直接显示“人 #1、汽车 #2、公交车 #3”等类型与编号，和下方列表一一对应；每个类型使用固定颜色。标签会尝试在物体外寻找空位，并通过短线指回对应框。密集场景仍可能拥挤，因此提供类型筛选、选中后单独查看、隐藏名称、无框预览和全屏。网页标记根据实际解码时间显示，不拿前后帧的框填补漏检。标注下载及证据截图沿用相同的颜色和标签方式。

## 识别设置

上传使用官方预训练YOLO11s，已验证的CUDA环境优先使用GPU，CPU回退为4线程。普通画面960输入；密集且不超过30秒的视频使用1280输入，更长的密集视频保持960。密集模式调整重叠抑制阈值，保留相互交叠的候选，上限200。配置见`vision/upload-detection.json`，模型校验仍见`vision/upload-model.lock.json`，没有训练新权重。[密集场景修正与对照](crowd-detection.md)。已有演示和专项复核的 YOLO11n 权重、数据和结论保留原版本。[GPU实测与失败恢复](upload-performance.md)。

视频仍以每秒5帧处理，2分钟最多600帧，任务上限300秒。不超过30秒的视频保留到1920×1080以内，竖屏交换长短边；其余视频和图片仍保留到1280×960以内，不放大原素材。ByteTrack以0.25为新记录门槛；0.1—0.25的弱检测只用于关联已有记录。不同类别分开跟踪，避免人车相互关联。保留检测框在高/低置信度子集筛选前的索引，防止重复指向同一个框。绘制坐标来自当前检测框，跟踪器只提供编号，以避免低帧率下平滑坐标落后于快速移动的汽车。记录类型使用各次分类置信度加权投票，降低偶发类别跳变。

低清提示使用输入的真实尺寸判断。导出时放大画布是为了文字可读，没有对推理输入进行生成式修复，也不声称恢复被遮挡或丢失的细节。被遮挡的人、反光、广告人物、远处小目标仍可能漏检或误判；跟踪记录数仍不能代表全片唯一人数/车辆数。
