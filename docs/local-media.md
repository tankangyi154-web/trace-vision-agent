# 本地图片/短视频处理

当前入口是 `http://127.0.0.1:8000/`：上传文件，手动填写或从列表选择1—3种物体再开始分析，查看标注结果后提问。“用示例体验”及创建示例上传的API已取消。手填支持中英文及常用别名，确认添加后显示规范名称；未知名称不加入识别范围，未确认的输入阻止开始分析。留空不会上传或运行检测，API同样拒绝空选择。后续问新物体会继续补查当前素材；每条提问最多新增3种，累计可超过3种。历史区域/阈值/复核案例保留为项目原理中的次级入口。源代码旧基线保留，本轮使用product/local-media-assistant分支。

## 实际处理

API不载入Torch：在独立UUID临时目录接收有界文件，再启动无应用密钥的视觉子进程。JPG/PNG/WebP图片最多20MiB、2000万像素；MP4/MOV/WebM短视频最多200MiB、2分钟。服务检查实际字节、可解码类型、尺寸、视频元数据和实际抽样帧数。图片和超过30秒的视频保留到1280×960以内；不超过30秒的视频保留到1920×1080以内，竖屏交换长短边，不放大小尺寸输入。视频5fps，最多600帧；输出VP9标注视频及私密无框预览。超长文件拒绝，不作为截短成功返回。

上传使用固定YOLO11s，已验证的CUDA环境优先使用GPU，否则使用CPU4线程，普通画面960输入；检测到至少12个高置信度行人或24个所选物体时，密集模式使用0.65重叠抑制阈值，不超过30秒的短片另采用1280输入。单帧上限200个候选，整段只增加一次模式探测复算；长片保持960输入。配置及摘要写入结果的processing，权重由`vision/upload-model.lock.json`校验；原有三个预生成案例与专项复核仍使用原YOLO11n。可选择80种COCO常见类别，类别过滤实际传入YOLO。图片置信度0.25；视频检测下限0.1，让ByteTrack用弱检测关联已存在记录，新记录门槛仍为0.25；行人采用本地OSNet外观核对，交叠时不更新长期外观。没有干净起始画面的目标，只允许用相邻两帧的严格位置、外观和颜色一致性确认编号；跨缺帧、弱候选或歧义关联仍不能借用旧编号。画框采用当前检测坐标，不填补未检测到的帧。同一记录按置信度加权确定一种类别，以减少标签和颜色跳变。没有训练新权重，每次处理仍与输入SHA256绑定。[密集场景对照](crowd-detection.md)。

画面始终显示类别与编号（如“人 #1”“汽车 #2”），与下方物体列表逐一对应；同类固定颜色。标签尝试在物体外避让，不遮住其他标签。可按类型筛选、单独查看选中物体、隐藏名称、切换无框画面及全屏。导出的标注视频和截图采用同一配色与标签避让，低清输入的导出画布适当放大以保证文字清楚，不宣称恢复真实细节。短片抽检与已知限制见[识别改进验证](upload-recognition.md)。

补查只对尚未完成的新类别运行YOLO，使用同一规范化素材、帧网格及固定配置；校验原素材和缓存SHA256，保留原目标编号及真实观测，新目标继续编号。标注媒体和截图按修订版本保存，旧引用仍可回看。页面自动刷新累计查找范围与合并标注；补查失败保留原结果并明确未完成，不能将其说成未检出。

上传流程单worker，最多三个在途文件。实际进度来自接收/读取/加载/检测帧/渲染阶段，不显示虚假进度。GPU或≤150帧CPU任务300秒上限，较长CPU任务900秒上限；FFmpeg子任务另有120秒时限。前后端共用`data/media-limits.json`，上传接收、排队查询及补查问答的等待时限与视觉任务预算配套；公开视频案例的模型调用时限不变。Windows Job Object将Python及FFmpeg子进程一起归属管理；取消/超时/关闭均终止子进程树，确认清理后才报告删除完成。API意外退出时Job句柄关闭，子进程退出；下次启动清理管理进程已退出的临时作业。取消清理已实际复现验证，未逐一模拟所有异常关机/崩溃情形。

## 结果与追问

输入区采用一个统一外框，Enter直接发送、Shift+Enter换行。中文输入法选字时不发送，按住回车不重复提交。原有案例问答采用相同键盘行为。

自动摘要由本次实际统计生成，首先显示标注图/视频。关键画面来自标记最多或新类别出现，不解释为事故/异常。每个目标都保存自身首次和末次的真实截图，截图集合不超过600个采样帧。点击标记高亮对象；截图可放大，视频可以定位到该时刻。

`MediaTools`绑定当前上传：detect_objects补充识别，count_objects对尚未查过的具体类别也自动补检；locate_object、get_highlights、get_evidence查询已完成的真实结果。“全部”指当前累计查找范围，不擅自启动80类检测。图片数是检测实例；视频数区分跟踪记录和单帧最大值，不能当作不同物理物体的精确总数。时刻对应5fps抽样结果，不是实际进入/离开时刻，不将采样间隔当作连续证明。

指定编号的多问题会逐项核对出现时间、画面路线、末次识别及中断记录、性别、体型、身高等已支持的提问方面。明确给出至多两个编号时，服务端先执行真实的locate_object查询，计入原有5次工具预算，工具记录标明question_plan；不是额外的模型调用。即使模型只选首次出现的事实，服务端仍按本轮查询结果补全已识别的提问方面，并返回answer_coverage，不能用模型自由描述填补缺失事实。

原问题、实现边界与实际验证见[多问题回答](multi-question-answering.md)。

路线将实际识别框中心概括为画面九宫格位置，过滤短暂跳动，最多保留四个代表位置，不补画未识别时段。未识别段按5fps的缺失采样统计，末次识别与视频结束的时间差不等于实际消失时长。外观与动作提问会通过locate_object实际提取该编号的较清晰画面，发送上下文与局部放大供多模态模型分析；衣着、外轮廓、可见姿态据图描述，看不清时具体解释。外观呈现与实际性别身份分开表达；身高仅在完整站姿与具体参照具备时提供宽范围的目测估计，标明参照尺寸是假设、并非测量，无参照不猜数值。单张图只描述姿态，不确认持续静止或移动。回看引用绑定所问编号，包含实际选出的截图。[实现与验证](target-visual-analysis.md)。

全局“谁出现最久”用rank_objects按类别分别比较实际累计识别时长或最长连续区间，不计漏检间隔。与指定编号外观混合提问时，先执行全局比较再取图，逐项纳入answer_coverage；排名对应的证据回看会切换到获选编号。

追问复用有界LangGraph、幂等、额度和真实供应商用量，最多3次模型/5次工具。普通数量/时序问题只发送结构化记录；外观/动作问题最多发送两个编号、六张受控JPEG卡片，不发送完整原始媒体、私密访问URL或令牌。截图附在同一次模型请求中，图像用量包括在供应商真实计量内，没有隐藏的旁路模型调用。数量、单位、类别与时间仍从fact_keys确定；视觉解读通过visual_observations绑定本轮实际目标截图、可信程度与具体不足原因，factual_basis用source区分视觉模型解读和确定性观测。无效引用、估造真实身高/体重/年龄数值、明显低分辨率下的过度外观断言可在原预算内修正。补查保留旧截图引用并重算已有汇总。引用和格式校验不能证明所有视觉语义准确，仍可能需要人工审阅。

## 本机识别记录

所有上传与派生结果在被Git忽略的work/uploads内。原始上传和无用中间文件在首次处理结束后删除；保留私密规范化PNG/MP4副本供补查与无框预览。完成的结果不再按30分钟清理，改为本机识别记录，直到用户明确删除；失败或空闲未完成任务按30分钟时限清理，当前服务正在处理或排队的作业不会因该时限被误删。分析新素材、刷新、切换记录及服务重启不删除已完成结果。未被旧版定时清理的完成记录自动迁移；已删除文件无法恢复。实现与验收见[记录与恢复](local-records.md)。

浏览器用小型持久引用恢复当前记录、初选物体、所选目标与播放时间；待分析文件在IndexedDB暂存30分钟，完成后删除浏览器草稿，继续使用本机结果。暂时网络失败保留引用并提供重新连接，仅API明确not_found才清理失效引用。记录列表只返回提交了对应所有者凭据的记录，图片/视频仍使用独立随机资源令牌和no-store。保存记录的访问凭据与实时提问会话分离，切换旧记录不要求重新识别，也不重新分配模型额度。

主动删除同时清理规范化副本、所有版本、看图卡片、SQLite中该上传的请求结果/聊天历史；终态结果及历史写入使用同一事务，不能在删除后重新插回私密历史。其他素材不受影响，已调用用量不回退。浏览器缓存、私密访问链接、上传副本和结果均不加入源码包；模型仅按问题取得必要的结构化记录或选中截图。

当前上传仅在本地默认SQLite模式开放。不会把上传素材写入公开媒体目录或源码包。测试录屏/验收凭据使用本项目有署名许可的公开视频派生新文件，属于明确保存的验收制品；应用不会替访客导出私密素材。

## 换机器准备

本机已准备，无需重复覆盖现有配置。若复制源码到新机器，先依README准备API与前端，再准备以下本地推理依赖：

```powershell
python -m venv work/vision-env
work/vision-env/Scripts/python.exe -m pip install -r vision/requirements.txt
python vision/download_model.py
```

安装FFmpeg并加入PATH，或将ffmpeg.exe放在work/bin。权重、虚拟环境和FFmpeg不打进源码包。`DEEPSEEK_API_KEY`只在私密.env.local配置；没有Key也可真实检测，追问明确不可用。不要覆盖已有.env.local；不需要Upstash或部署账号。素材与开源许可延续THIRD_PARTY_NOTICES.md及media/ATTRIBUTION.txt。

## 公开部署取舍

本轮没有公网发布。保留本地推理成本最低；以后若让远程访客上传，需独立CPU推理服务、受控队列、隔离临时存储和访问/清理机制。Vercel静态/轻量API方案不能单独承担当前Torch上传worker。是否购买算力、支持多长视频和并发人数，留待用户授权上线时按成本决定。


## 分析范围、等待与重复结果

默认完整视频，用户可在分析范围中显式选择时间段；所有结果时间相对所选片段起点，页面保留原片起止提示。相同所有者、原片SHA、初选类别集合、范围及算法配置匹配才复用完成结果；选择同一文件仍需接收内容和计算摘要。识别阶段在至少10帧后显示实际速度推算的剩余时间区间，导出阶段显示正在整理。CPU选择、便携版与验证边界见[本地交付](local-delivery.md)。
