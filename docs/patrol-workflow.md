# 巡查复核：从片段定位到证据单

当前三个公开视频案例提供同一条可操作流程：程序整理与所选范围有关的片段，使用者回看对应时间、查看实际截图，记录核对结果与说明，再导出核对单。该流程用于帮助定位与复查视频事实，未定义行业执法、异常风险评分或真实身份判断规则。

## 可以实际操作的两个任务

- 右侧水面，7秒条件：船舶连续识别9.4秒，回看片段包含1.0—10.5秒及已观察到的离开。首次识别时已在范围内，不将其称为一次进入。12.3秒之后的识别中断发生在离开该范围之后，不列入这个范围的复核重点。
- 水道中部，5秒条件：累计识别5.7秒，最长连续区间3.7秒，中间0.8秒无法确认。清单保留证据不足，提供现有船舶专项复核入口；实际复核策略与结论独立显示，不能把人工点击或累计时长当作连续性证据。

同一次区域出现中的进出、达到所设时长及相关中断合并为一条片段记录。只有一条时直接显示内容，多个片段时提供列表选择。原始时间线、全片截图与程序统计仍可展开核对。

## 保存、隔离与导出

人工结果只有「已核对」和「仍无法确认」，尚未填写的记录为「待核对」。人工意见不会覆盖程序计算，也不会自动写成模型事实。浏览器保存最近400条有效记录，说明最多1200字；不可保存时明确提示，页面内记录仍能导出。当前没有跨设备同步或多人审批。

`review_scope_id`由源视频版本、实际轨迹观测、区域几何、抽样参数、模型/跟踪器版本、规则版本和时长设置生成。修改上述条件后，旧人工意见不套用到新结果；回到相同设置时，可恢复对应记录。

HTML核对单包含当前设置、程序事实、人工意见、时间、数据版本与实际JPEG截图。截图以数据形式嵌入，可离线打开；若截图获取失败，会保留明确说明和本地回看地址。导出前不把用户说明作为HTML执行，不获取范围以外的URL，也不包含模型密钥。JSON记录适合进一步核查与程序处理。

本次浏览器验证导出的演示文件，由自动化操作填写测试核对意见，不能视为独立人工评测结果。上传工作台仍提供其原有的识别与问答流程，当前巡查清单适用于三个已配置区域的公开视频案例。

## 如何验证实际效率

见`evals/patrol-task-study.template.json`。以相同的查找、核对和留证任务对比人工方式与辅助方式，记录耗时、遗漏、误报、结论正确性与证据可追溯情况。应使用独立授权的1—2分钟多目标素材，并交叉安排操作顺序，避免把熟悉短案例产生的加速当作产品收益。

当前已验证功能与事实边界，尚未完成独立人工效率测试，不展示节省时间比例或问答准确率。自动化浏览器运行耗时不能替代人工任务耗时。
