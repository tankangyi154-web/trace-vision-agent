## 实现与复现

- 检测器和人物外观编码器共同使用GPU，跟踪关联继续在CPU上执行。模型权重、5fps采样、960输入、跟踪门控与FP32精度保持不变。
- 标签避让使用批量数组计算；保留原候选位置、碰撞权重和顺序选择。80个框的本地排布核对结果一致。
- 在同一视频第0、150、400个采样画面做CPU/GPU数值核对：三帧的高置信框数量分别为12、15、18；按类别寻找最佳匹配的最低IoU均大于0.999。外观向量余弦距离约7.75e-7。[数值核对](../evals/gpu-numerical-check.json)仅检查数值偏差，没有逐目标标注，不能当作准确率评测。
- `processing.device` 与 `processing.timings` 记录实际设备和阶段耗时。硬件差异、目标密度和同时运行的程序都会影响耗时。

已完成基础安装后，可在Windows运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup_gpu.ps1
```

此脚本使用独立的 `work/vision-gpu-env`，固定PyTorch 2.7.1/CUDA 12.8与torchvision 0.22.1，以及其余项目依赖。GPU依赖依据[PyTorch官方Blackwell/CUDA 12.8支持说明](https://pytorch.org/blog/pytorch-2-7/)选择。必须通过CUDA运算、YOLO检测、OSNet特征提取三个检查，才写入就绪标志。随后重启服务启用。CPU环境保留；未准备GPU环境时选择CPU解释器，GPU运算不可用时在视觉子进程内回退CPU。CPU处理长视频会慢很多；当前GPU或≤150帧CPU任务上限300秒，长CPU任务上限900秒。新增CPU数值对照和便携版验证见[本地交付](local-delivery.md)。

## 失败恢复与页面反馈

- 超时与一般处理错误分别记录，保留已完成画面数，不再把所有失败解释成文件问题。
- 原文件转换完成后，保存经过校验的本机素材副本与摘要。失败后点击“重试当前素材”，重新执行分析，沿用同一记录，无需再上传原文件。这里复用的是素材，尚不支持从中断画面续算。
- 每次重试核对素材副本的SHA-256、源文件摘要、固定文件名与尺寸/时长边界；保持原来的所有者检查、队列上限和私有资源白名单。副本缺失或超过临时保留期时，需要重新提交文件。
- 失败素材仍只暂存30分钟，已完成的识别记录保留到手动删除；重试不会将未完成结果标为成功。
- 页面区分等待、读取、识别、标注导出，显示已用时间。识别完成后继续显示“正在整理”，避免进度到100%却看似卡住。
- 浏览器实测：3秒片段先完成一次识别，在专用失败测试记录中移除原上传文件，随后直接重试；收到15/15帧完整结果，上传次数为0、重试次数为1，刷新后仍保留结果与选中的编号。本轮测试记录已删除，用户原117秒识别结果保留。
