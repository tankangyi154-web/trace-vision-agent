# Agent回答优化方案

日期：2026-11-03。下文保留最初建议方案；查询规划、简洁表达、按问题取图、私有缓存与有界评测已经实施，详见[实施结果与真实验证](agent-answer-implementation.md)。身高已补充[公开数据分层对照](height-validation.md)，仍为实验性粗估。用户后续选择先做AI复核，该范围已完成；[AI复核报告](ai-evidence-review.md)不冒充真人独立评估。

## 目标

HR能快速理解“找到了什么、凭什么这样说”；技术负责人能继续查看真实取证、计算及验证范围。优先保证完整、简短、能回看，再增加能力。

## 当前代码暴露的问题

- `api/media_profile.py`主要依赖关键词、正则表达式及固定类别拆解提问。已修复的问法可以工作，换说法、否定、条件或指代仍可能识别不完整。
- `api/media_tools.py`已有覆盖检查，但覆盖范围取决于前面的解析。正文主要拼接固定事实句，容易重复编号、解释和限制。
- 上传问答上下文没有单独传递当前选中编号。“他呢”“另一辆呢”可能同时对应历史答案里的多个对象。
- 取图主要按通用清晰度、大小和时间段评分，同一套选图不能同时保证衣着近景、完整身形和动作前后关系。
- 已有接口、前端回归与少量真实模型用例。它们能证明特定流程可运行，不能代表真实回答的完整率、引用正确率或外观准确率。身高粗估目前没有已知真实身高的误差评估。

## 第一轮：理解完整，表达自然（优先）

### 1. 统一问题清单与指代

保留简单问题的快速路径。对复杂、多轮问题，增加结构化问题计划：对象、所问属性、比较方式、时间范围、来源及待回答项。计划必须通过类别、编号、当前素材及工具预算校验。

例如“谁待得最久，另外看看48号穿什么”拆成“累计出现时间排名”和“48号衣着”。“他呢”优先结合当前选中编号；历史中有多个可能对象时简短澄清，不擅自挑一个人。增加模型规划只用于复杂情况，仍控制在现有三次模型、五次工具预算内。

验收：准备至少30组真实问题及同义改写，覆盖多问、指代、否定、并列、不同类别及目标切换。清单内的每项都必须有回答或具体未完成原因；单独统计拆解错误，不能由模型自己宣布完整。

### 2. 短答与依据分层

默认先给一段简短结论，复杂问题最多几条短句；通用限制集中说一次。证据、逐项理由及技术记录按需展开。数字、时间和编号继续由真实事实填入；模型负责组织自然表达，输出结论逐项绑定事实与截图，不能改写数值。

目标表达示例：

> 出现最久的是人 #1 和汽车 #36，累计分别为15.2秒和7秒。48号外观偏男性化，身形中等偏结实、肩背较宽；身高缺少可靠参照，暂不能估计。

示例数字来自已有集市验证记录，仅展示建议的表达结构。保留每项的“观测事实／视觉解读／依据不足”属性，不将某一项不足显示成整份回答均无效。

验收：首屏能找到核心答案；不重复每条共有的限制；简化后仍覆盖全部所问方面，引用与事实校验继续通过。

## 第二轮：让取证更符合问题

### 3. 按问题选图，检查编号一致性

衣着优先清晰近景；身形优先完整站姿；动作优先有时间关系的前后画面。选图去重，复用现有每个目标最多三张的预算。多个所选画面的衣着或位置明显不一致时，先标出编号可能混淆，不把它们当作同一个人来描述。

每条主要结论提供“看人 #1”“看汽车 #36”“看48号外观”等对应入口，减少四张截图只标时间、用户不知道支持哪句话的情况。现有回看切换编号行为继续保留。

验收：证据属于正确素材、修订和编号；点击后看到相应对象；动作结论有连续时刻支持，静态图不被写成持续行为。

### 4. 有条件地推断，具体解释不足

可见衣着、身形与姿态正常描述；明确将外观呈现与实际身份区分。身高粗估增加已知参照录制片段及人工核对，记录假设、远近关系和误差。没有参照时说明缺哪项，不以没有个人档案为由拒绝其他可见内容，也不按平均身高填数字。

验收：先用有已知参照与真实身高的材料验证，再决定是否适合放入招聘演示；未通过的估计保留为实验功能。这里不给出尚未测得的误差承诺。

## 第三轮：稳定性、等待时间与可展示证据

### 5. 建立独立的回答评估

从约五类素材建立小型人工核对集：清晰近景、低清远景、密集遮挡、没有所问物体、单张图片。分别记录问题漏答、事实错误、引用错配、不必要拒答与无依据推断；不要将接口测试通过率、检测框数或模型自评分叫做回答准确率。

保留同一输入、识别版本、模型及提示版本，比较优化前后。检测错误、跟踪串号、Agent理解错误分别记录。付费评测显式限制样本数和调用预算，先跑小批次；人工核对后发布失败案例及边界。

### 6. 简单问题直接查，重复问题复用

“哪个编号最久”“什么时候出现”等确定性问题可直接返回程序结果，减少模型等待。视觉提问复用已经取得的截图与已验证的同类解读。缓存按所有者、素材修订、目标、问题意图、模型与提示版本隔离；换对象、补查新类别或更改问题范围时失效。

验收：不显示其他素材或其他用户的旧答案；显示真实进度；失败重试不生成重复请求或重复付费调用；记录实际等待时间再比较效果。

## Skill选择

输入框使用已经安装的`ui-ux-pro-max`。通过find-skills目录检索并核对后，已安装社区skill [llm-evaluation](https://www.skills.sh/wshobson/agents/llm-evaluation)，采用自动检查、人工核对和前后对照的方法。它的[源仓库为wshobson/agents](https://github.com/wshobson/agents)，安装本身不提高模型的语义准确率。

官方目录提供的安装方式可加全局与非交互参数：

```text
npx skills add https://github.com/wshobson/agents --skill llm-evaluation -g -y
```

这些热度数字仅用于候选核对，不代表能直接提升项目模型的语义正确率。实施评测时按当前项目裁剪，无需为此引入新的线上服务。
